# orderby missing field invisibility

> "Firestore orderBy silently drops docs missing the field — bulk loads without createdAt made all 1,817 Sodexo contacts invisible on /contacts"

2026-08-11: Greg couldn't find Paul Mixa (a hot Sodexo reply) on the /contacts page even though the doc existed. Root cause: RecruiterContacts.tsx loads with `query(contactsRef, orderBy('createdAt', 'desc'))`, and Firestore EXCLUDES documents that lack the orderBy field entirely. The SDX-4 Sodexo campus load (2026-07-14) wrote 1,817 crm_contacts without `createdAt`, so the entire cohort was invisible on that page for a month — while remaining fully visible to campaign scripts and server scans that don't order by it.

**Why:** Distinct from the [[feedback_undefined_stripper_timestamp_footgun]] (corrupted timestamp VALUES); this is a MISSING field. Same symptom family: docs silently vanish from ordered queries with no error anywhere.

**How to apply:** Every bulk loader/importer must stamp `createdAt` (and `updatedAt`) — check this in review for any script that writes list-rendered collections. When a user reports "doc exists but doesn't show in the list," check the list's orderBy field on the doc FIRST. Backfilled 2026-08-11 via .scratch/backfill-crm-contacts-createdat.ts (stamped real load date 2026-07-14 so newest-first sort stays honest); orderBy query went 1,798 → 3,615 docs.

**2026-08-11 full-audit follow-up** (.scratch/audit-missing-createdat.ts + backfill-missing-createdat.ts, all backfills use honest per-doc dates and re-check at commit time): also backfilled 232 sdxloc_* locations + 232 sdxacct_* accounts (same Sodexo scrape, dated from load-time updatedAt), 64 users (Auth creationTime else earliest doc timestamp), 4 crm_locations shells (from associated deal createdAt), HRX tenant doc, and 1,155 applications (createdAt := submittedAt/appliedAt — live writers Wizard.tsx submit + partial-save and quickApplicationSubmit.ts NEVER stamped createdAt; patched with read-guarded createdAtStampFor() in src/utils/applicationCreatedAtGuard.ts on branch claude/great-gauss-1f547e). crm_companies/crm_deals/job_orders/job_postings were clean. NOT stamped: 96 assignments shells + users/test-* ghosts (merge-write resurrections of deleted docs — separate cleanup) and 1 orphan crm_locations shell. Related latent bug: 714 location docs carry createdAt as ISO STRING (UI writers use new Date().toISOString(), e.g. RecruiterAccountDetails.tsx:3244) — visible but mis-sorted (Firestore type-bucket ordering), separate fix.
