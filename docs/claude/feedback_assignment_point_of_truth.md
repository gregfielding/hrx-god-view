# assignment point of truth

> "Greg directive 2026-08-05: fill data holes by MATERIALIZING assignments (rate/company/worksite/WC), never read-time patches — completeVenueMapping is the pattern; apply to timesheet processing too"

Greg's architecture directive (2026-08-05, Minnesota Yacht Club mapping): the **assignment is the single point of truth** — it carries rate, company/account, worksite, WC code/rate, position. Any "fill the gap" tooling must repair the SPINE (create/complete assignments and stamp entries), not patch attribution at read time; read-time patches leave payroll/WC hollow and the hole reopens every import. Goal: with holes filled during weekly processing, month-end unattributed payroll ≈ 0.

**Why:** the original venue→JO mapping was a report-layer label patch — dollars reported right while no assignments existed (79 MN Yacht Club workers), so WC, rates, and future pairing stayed broken.

**How to apply:** `completeVenueMapping` callable (payrollCostReport.ts) is the canonical pattern — wizard (JO + position + rate source) → dry-run preview → creates one assignment per worker from paid entries (actual paid rate default; ongoing JO ⇒ open-ended assignment so the date-window pairAssignment matcher catches future imports; closed JO ⇒ dated window + status ended), WC via title→state-default matrix chain, entries stamped with assignmentId/JO/account/WC. Retro-created assignments MUST carry `retroactive: true` + `notificationsSuppressed: true` + `suppressInitialNotification: true` (existing trigger contract — no SMS/push to workers) and `assignmentSource: 'venue_mapping_backfill'`; skip onboarding instances. Anchor id `${openOrFirstShiftId}__${userId}` (surrogate `jo_<joId>` when the JO has no shifts).
