# ai automation ethos

> Greg wants bleeding-edge AI/automation baked into every HRX build step; recommend forward-thinking ideas as we go

Greg's directive (2026-07-17): HRX exists to help C1 "work smarter, not
harder" — staffing is low-margin, so the path to profit is automating away
labor cost, not adding headcount. He explicitly wants to leverage the
bleeding edge of what Claude/AI can do, and asked me to **recommend
forward-thinking automation ideas at each step**, not just implement the
literal ask.

**Why:** low-margin industry; cost-to-serve per placement is the lever.
Every recruiter-hour spent on data entry / portal-watching is margin lost.

**How to apply:** at each phase/step of a build, proactively surface 1-3
concrete AI/automation ideas with a rough ROI + effort/risk tag. Frame the
north star as: HRX becomes an **autonomous coordination layer** that watches
the Flex/Fieldglass portals, keeps itself in sync, fills gaps, predicts
no-shows, and only escalates exceptions — recruiters shift from data-entry
to exception-handling + relationships. Ground ideas in the real stack (they
already run OpenAI gpt-5 via appAi.ts, a Fieldglass Chrome extension,
Twilio SMS, SendGrid inbound parse, `noShowRiskPredictionV1` +
`assignmentReadinessV1` fields on assignments, Everee payroll). Be honest
about which ideas are table-stakes vs bleeding-edge/higher-risk. See
[[project_scheduling_system_review]] for the phase roadmap these attach to.
