# undefined stripper timestamp footgun

> "Object.entries-based undefined-strippers collapse Date/FieldValue/Timestamp into plain maps — corrupted 180/268 job_orders createdAt to {} in prod; use stripUndefinedDeep or a plain-object prototype guard"

Deep "remove undefined for Firestore" helpers that rebuild objects via `Object.entries` destroy class instances: `Date` and admin `FieldValue.serverTimestamp()` have zero enumerable own props → become `{}`; client `Timestamp` becomes `{seconds, nanoseconds}`. Firestore sorts maps above timestamps, so any `orderBy('createdAt')` pins corrupted docs to the wrong end.

**Why:** Found 2026-07-08: 180/268 prod job_orders had `createdAt: {}` (JobOrderForm.tsx `removeUndefinedValues` + gigJobOrderFromChildAccount.ts `stripUndefined`), 39 job_postings had flattened Timestamp maps (jobsBoardService.ts). All three fixed (commit 9c823d4a, merged to main b67af39a) with a plain-object prototype guard; deployed 2026-07-09 (scoped: onChildAccountCreatedAutoCreateGigJobOrder + backfillGigJobOrdersForNationalAccount, plus hosting) and prod backfilled via `functions/.scratch/backfillJobOrderCreatedAt20260708.ts` (createdAt ← doc createTime, flattened maps restored exactly; rerunnable mop-up). The helper was copy-pasted across the repo; 2026-07-09 follow-up (commit 56966e4e, deployed) hardened all nine remaining copies (DealDetails, ContactDetails ×2, activityLogger, jobOrderService inline, cleanupUndefinedValues callable, contactEnrichment, simpleEnrichCompanyOnDemand, accusource webhooks) — survey showed CRM collections clean (their serverTimestamp() stamps sit outside the cleaners) and one corrupted users doc (JSON-serialized sentinel), repaired. New copy-pasted cleaners can still reintroduce the bug.

2026-07-09 later same day: a second pass (branch claude/objective-fermi-867710, commit 75eb1919, rebased onto 56966e4e) consolidated the src/ copies onto a new shared client util `src/utils/removeUndefinedDeep.ts` (exports `removeUndefinedDeep` + `isPlainObject`; JobOrderForm/jobsBoardService/DealDetails/jobOrderService now import it; the null-dropping cleaners keep local semantics but use `isPlainObject`; UserProfile's shallow filter now routes through removeUndefinedDeep). A deep NESTED survey (`inspectTimestampFields20260709.ts` — top-level createdAt/updatedAt were all clean by then) found corruption below top level that the 20260708 backfill didn't cover: job_postings `postedAt` ×73 / `nextShiftDate` ×23 / `translationMeta.es.updatedAt` ×12 as {seconds,nanoseconds} maps (postedAt feeds JobsBoard sort), job_orders `deal.updatedAt` {} ×180, crm_deals `associations.locations[].updatedAt` ×2; users + activityLogs (20k sample of 158k) clean. Repaired via `backfillNestedTimestamps20260709.ts` (flattened maps → exact Timestamp anywhere; `deal.updatedAt` {} → doc createTime, allowlisted) — re-survey verified 0 hits. Lesson: when this bug class hits a collection, audit ALL timestamp-typed fields (nested included), not just createdAt/updatedAt.

**How to apply:** When writing/reviewing any Firestore payload cleaner, only recurse into plain objects (`Object.getPrototypeOf(v) === Object.prototype || null`) — the canonical impl is `functions/src/utils/stripUndefinedDeep.ts`. If a doc field that should be a Timestamp sorts weirdly or reads as `{}` / `{seconds,nanoseconds}`, suspect a cleaner in the write path. Doc metadata `createTime`/`updateTime` are the exact repair source for collapsed `{}` values. See [[scoped-functions-deploy]] before shipping server-side fixes.
