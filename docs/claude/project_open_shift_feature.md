# open shift feature

> "Spec for the \"Open Shift\" feature (date-range, no-times standing-crew shift) — agreed product decisions + slice plan, before/while building"

**Open Shift** = a shift that's a date range with **no fixed times**; recruiters place their regular crew on it, real assignments are created, and timecards are filled from the hours the client sends weekly. It's an attendance/roster container, not a scheduled shift. Use case: same crews ongoing at a worksite where the client manages the schedule and just sends hours.

**Agreed product decisions (2026-06):**
- **Timecards:** recruiter fills hours **weekly in the timesheet grid** (draft entries generated **per pay-period on demand** when the grid is opened for that period — never materialize infinite days; reuse `actualHoursOverride`/duration entry).
- **Worker view:** **informational only** — shows in their assignments with explainer text ("schedule set by your C1 recruiter/manager"), nothing to confirm/decline.
- **Duration:** **ongoing / rolling, no hard end** (`endDate: null`); needs a **close-out** action (stamp end date on the assignment to remove a worker from the crew, or on the shift to end it).

**Data model (proposed):** shift doc `shiftType: 'open'`, `startDate`, `endDate: null`, `noFixedTimes: true`, `hideFromJobsBoard: true`. Open shifts are inherently multi-day on **any** JO type (bypass the gig-only multi-day gate in `EditShiftForm.tsx` ~line 1124-1127 / 1097-1418 that deletes `endDate` for non-gig). Assignment: `isOpenShift: true`, no times, status `active`, no offer/confirm SMS.

**☠️ Career workers on a single-date shift got ONE timesheet row per week (found + fixed upstream 2026-09-11).** Fieldglass-intake shifts (`createdBy: system_fieldglass_auto`, `shiftMode: 'single'` + `shiftDate`; standard with times when the schedule text parsed, else `shiftType: 'open'` + `autoCreatedOpenShift`) are also used for CAREER placements. The one-weekday schedule was NOT written by placement code: `placementsCreateAssignments` writes no `weeklySchedule` on a career single-date hire (and `endDate: ''`), so `onAssignmentWriteEnsureDenormFields` → `resolveWeeklySchedule` filled the gap by synthesizing one from the shift's `shiftDate` weekday (its per-day remap only applies when startDate === endDate). Placement source is irrelevant — JO #404 had `search_all` AND `applicants` hires hit. The grid resolver emits rows only for enabled weekdays and `createDraftTimesheetEntryCallable` rejects other days, so a full-time worker couldn't be timecarded Mon–Thu. Symptom: "X started 9/1, only the Friday row shows."

**Fix:** `functions/src/timesheets/careerWeeklySchedule.ts` — career + not per-day + shift has no weeklySchedule of its own → Mon–Fri at the shift's times, plus the start date's weekday when it's a weekend. Applied (1) in `resolveWeeklySchedule` (every writer, incl. the backfill callable); (2) in `placementsCreateAssignments`, stamped at create/reactivate from an optional `weeklySchedule` payload, else the default; (3) in Natalie `placeWorkerOnShift`, which also stamped `endDate = date` + one weekday on career orders. PlacementsTab asks "Which days will X work?" (Mon–Fri pre-checked, shift times) before a career hire onto such a shift — drop, Click to Hire, pool assign, bulk accept. Gig and per-day docs keep the single-weekday shape (correct for one-day gigs; `addRetroactiveWorkerCallable` / Indeed Flex `portalIngest` are per-day writers, untouched). Tests: `functions/src/__tests__/timesheets/careerWeeklySchedule.test.ts`.

**Never "fix" these by stamping `isOpenShift`/`noFixedTimes`:** it switches the worker to the open-shift model (a blank no-times row every calendar day, "no set times" worker card, open-shift cadence fences), and the ONLY thing keeping `completeExpiredOpenShiftAssignments` from completing them at the next 13:00 UTC is its `jobOrderType === 'career'` skip for empty-endDate docs — a doc missing that stamp resolves its end from the single `shiftDate` (already past) and is flipped to `completed`.
