# tenantids map creation paths

> "Every users/{uid} creation path MUST write tenantIds.{T}={securityLevel,role,addedAt}; shared/tenantMembership.ts is canonical; legacy top-level tenantId+securityLevel alone = invisible user"

79 user docs in tenant BCiP2bQ9CgVOCTfV6MhD had top-level `tenantId` + `securityLevel` but no `tenantIds.{T}` map entry → invisible to Users search + Applicants list (both query `tenantIds.{T}.securityLevel IN TENANT_LISTABLE_SECURITY_LEVELS` = '0'–'4' string AND number forms, src/constants/tenantWorkerSecurityLevels.ts). Label-style levels ('Worker', 'Applicant_Worker', 'Manager') in the map are equally invisible — the IN filter never matches labels.

**Why:** multiple legacy creation paths each invented their own shape: `assignOrgToUser` wrote `tenantIds` as an ARRAY (clobbering the map), `inviteUserV2` defaulted the map level to the label 'Worker', three pages addDoc'd raw docs with no map, and the apply Wizard stamped membership only at step-0 save (signup dropouts stayed unlinked).

**How to apply:** `shared/tenantMembership.ts` (byte-mirrored at src/shared/, reachable in functions via the functions/src/shared symlink) is canonical for ALL membership-entry writers: `buildTenantMembershipEntry({securityLevel, role, addedAt})` normalizes labels→numeric ('Applicant*'→'2', 'Flex'→'3', 'Worker'/'*_Worker'→'4', 'Staffer'/'Manager'→'5', 'Admin'→'6') and derives role from level when role is missing/'Tenant' (2→Applicant, 3→Flex, 4→Hired Staff — same as the one-time backfill). All creation paths fixed in commit 3a29a98a (branch claude/laughing-villani-5bdf74): assignOrgToUser (dot-path map merge, array shape killed), inviteUserV2, updateUserLoginInfo, apply Wizard baseProfile, AuthDialog, AuthContext C1 fallback + non-C1 claims-derived stamp, OnboardingProfileForm, CustomerProfile/ContactsTab, AgencyProfile/WorkforceTab, AddUserForm. Any NEW user-doc writer must use the helper. One-time backfill for the existing 79: functions/.scratch/backfill-tenantids-map.ts — ALREADY EXECUTED; dry-run verified 0 remaining on 2026-08-07.
